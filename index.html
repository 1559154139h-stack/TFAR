01 · Overview

这是什么项目

长时程具身操作中，失败几乎不可避免：抓取滑落、物体位移、动作偏差。现有系统多依赖人工干预或盲目重试。本项目要回答一个核心问题——机器人能否像人一样"感知到要出问题了、并在恰当的时机用最低成本把它救回来"。

🎯

纯仿真、可复现

基于 MuJoCo 物理引擎与 robosuite，全部实验同种子可复现，结果可审计。

🧩

数据驱动选题

先用真实数据验证现象是否成立，再谈算法——避免"先发明方法、再找现象支撑"。

🔬

研究诚信优先

预注册门槛、Hard Cap、STOP 条件、结果不伪造；证明不了的结论如实写"不支持"。

📐

统一实验基础设施

02 · Problem

研究背景与核心问题

机器人一旦进入开放、动态的真实环境，一次抓取滑落或物体位移就可能让整条长任务链失败。而"恢复"本身就是个难题：盲目的重试可能浪费步骤，过早干预可能打断正常进度。

Q1 · 时序失败信念

只凭"当前这一刻"的状态判断是否失败，够吗？用一段短时序历史（物体位姿/速度、末端位姿、夹爪宽度、动作统计、进度、接触标志等）来估计失败概率，能否更早、更准地发现问题？

Q2 · 成本感知的恢复选择

面对失败，系统应在 retry / re-observe / adjust_pose / backtrack / replan 等技能中做选择——但选择必须考虑恢复成本（步骤数、重规划次数），而不是一律重试。

Q3 · 恢复头空间是否存在

如果无论早干预还是晚干预，结果都一样，那"自适应恢复"就没有意义。本项目用反事实验证专门检验：更及时的恢复决策，到底有没有真实的收益空间？

Q4 · 扰动与结果是否"解耦"

能被检测到的扰动，不必然导致失败；失败也不必然源于可检测扰动。项目用配对诊断（POD）厘清：哪些扰动真正是"捷径信号"，哪些只是噪声。

03 · Method

方法架构

核心科学结论（经严格审计）：在冻结的 C3 实现下，时序确认延迟并不能救回本不可恢复的状态；最稳健的策略是 robust failure-aware execution monitoring with fixed replanning（带固定重规划的失败感知执行监控），而非自适应恢复选择——项目如实把不成立的部分关闭，只保留被证据支持的结论。

04 · Journey

研究历程：从假设到诚实结论

这是一条"不断被自己的更严格实验推翻、再迭代"的真实科研路线——每一步都以预注册门槛和 STOP 条件约束，绝不为了好看而凑结论。

Phase 0–3 · 环境搭建与假设确立 完成

确定纯仿真路线；固定 Panda PickPlaceCan / robosuite 1.5.2 / MuJoCo 3.9.0 标准基线。定义 TFAR 假设：时序失败信念 + 成本感知恢复选择。

原始 TFAR 路线 经审计否定 · 关闭

连续控制实验系统性推翻了原始恢复假设的必要性与头空间，项目永久关闭该路线。

Runtime Robustness（P1–P3）跨对象不稳 · 关闭

发现 Can 任务上世界坐标方向各向异性，但跨对象后不稳定，如实关闭。

Claim-Aware Auditing（Q0）形成方法论

沉淀 6 类核心诊断：目标特征循环、时序必要性、严重度-结果混淆、排序-操作点差距、缺失决策头空间、跨条件/实现有效性。

外部验证 Audit（A1 / A1R / A1B / A-INFRA）基础设施验收

修复抓取验证与 runner bug；16/16 单元测试、12/12 runner 冒烟通过；验证非零扰动幅度、fail-fast 无注入保护。

数据优先现象发现（M0–M2E）只用真实数据

改为"先用已有/新数据找稳定现象，再决定选题"；发现 legacy provenance/schema 不可合并，坚决不 pool、不伪造指标。

POD · 扰动-结果解耦（P1R / A1–A4）80 对配对 · 结论确立

建立统一 Canonical Runner，完成 80 对同种子前瞻式配对；诊断确立扰动-结果捷径信号，得出 LITTLE SHORTCUT EVIDENCE，如实 STOP。

Phase-Conditioned Robustness 推荐方向 · 待启动

在现有 M1D / M1E / P1.5 / P1.6 / P2 数据上，先做 0-new-rollout 可行性审计，检验"阶段条件化的鲁棒性"是否存在可验证效应。

06 · Integrity

研究诚信与可复现原则

这套方法论让每个结论都可被他人复核、复现、证伪。

🚦

预注册门槛 + STOP 条件

每个阶段先冻结 protocol / gate / hard cap，再跑实验；结果弱就停止，不靠 post-hoc 调参救方向。

🚫

结果不伪造

无法公平执行的诊断，如实标注为"不可估计 / N/A"，而不是回填一个好看的数字。

🔎

泄漏审计

严格检查标签、特征、配对与数据溯源（provenance），杜绝任何形式的信息泄漏。

🔄

同种子前瞻式配对

干净/扰动分支同种子、同 runner、触发前完全等价，只留一个变量——公平比较的唯一正解。

⚙️

基础设施优先验收

先验证 runner / 注入 / 确定性 / Schema 正确，再谈科学结论，避免把基建失败误写成成果。

🧾

可追溯记录

原始结果只增不改、带种子标签；配置随结果存档；失败/中断实验也记录原因。
